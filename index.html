Backend Architecture

Patterns I use to build reliable, observable systems.

Model Fallback Routing

Resilient orchestration via Groq SDK. If the primary model (Llama 3.3-70B) fails or hits rate limits, the system automatically falls back to smaller models (8B) to ensure zero downtime.

Groq SDKLlama 3.3Failover

Zod Schema Validation

Every API request and LLM output goes through Zod validation. Invalid data is caught before reaching the database or external APIs, ensuring type safety across the stack.

ZodValidationType Safety

Prisma + PostgreSQL

Type-safe database access with Prisma ORM. PostgreSQL with migrations, relations, and atomic transactions. Audit logging for every data mutation.

Backend · AI Infrastructure

A production-grade Retrieval-Augmented Generation system over PDF documents with hybrid search, anti-hallucination grounding, and real-time token streaming via Server-Sent Events.

  • Hybrid RetrievalCombines vector search (pgvector cosine similarity) with lexical full-text search (to_tsvector) and metadata filtering, delivering 3× better recall on exact-value queries than vector-only search
  • Anti-HallucinationDistance gate (MAX_DISTANCE ≤ 0.5) ensures only well-grounded chunks reach the LLM; the system refuses to answer when no evidence passes the threshold instead of guessing
  • Query ExpansionAutomatically rewrites weak exact-value queries (e.g. "email" → "email address contact details") to maximize embedding recall without prompt injection risk
  • Real-Time StreamingToken-by-token responses streamed to the browser via Server-Sent Events, with source document attribution in the final SSE frame
  • Recursive ChunkingSplits documents at the largest meaningful boundary first (paragraph → line → word → character) with 512-token chunks and 20-word overlap for context continuity
